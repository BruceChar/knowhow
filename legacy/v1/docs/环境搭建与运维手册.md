## 2. 环境搭建（从头复现）

### 2.1 前置要求

- macOS（Apple Silicon / arm64）
- Docker Desktop 已安装并运行（`docker --version` 可执行）
- 使用 **compose v2**（`docker compose`，带空格），不要用 v1（`docker-compose`，横杠）

### 2.2 项目结构

```
knowhow/
├── docker-compose.yml     # PG18 + pgvector + API
├── Dockerfile
├── requirements.txt       # Python 依赖
├── .env                   # LLM_API_KEY 等密钥（不进 git）
├── app/                   # 应用代码（main.py / ingest / search / gate / eval）
├── docs/                  # 文档（本手册）
└── main.py                # 入口占位
```

### 2.3 启动数据库

```bash
cd /Users/bruce/python/knowhow
docker compose up -d db
docker exec rag_db pg_isready -U rag -d rag          # 等待输出 accepting connections
```


## 3. 踩坑记录（本次已解决，务必避免回退）

### 坑 1：`bad CPU type in executable` —— compose v1 架构不兼容

- **现象**：`docker-compose up -d db` 报 `fork/exec /usr/local/bin/docker-compose-v1: bad CPU type in executable`
- **原因**：`docker-compose`（横杠）软链到 Docker Desktop 捆绑的 **x86_64 版 compose v1**，与 arm64 芯片不匹配
- **解决**：改用 `docker compose`（带空格，v2.2.1 原生 arm64）
- **长期规则**：本项目所有命令使用 `docker compose`；教程代码中也是空格版

### 坑 2：端口 5432 被占用 —— 本机已有原生 PostgreSQL

- **现象**：`bind: address already in use`
- **原因**：macOS 上已有一个原生 PostgreSQL 服务监听 5432（`netstat` 可见 `postgres:328`）
- **解决**：compose 端口映射改为 `"5433:5432"`，连接串同步改为 5433
- **长期规则**：不要动本机 5432 服务；所有 DSN 写 `localhost:5433`

### 坑 3：容器启动即退出 —— PostgreSQL 18+ 挂载规范变更

- **现象**：容器 `Exited (1)`，日志提示数据目录格式与 `pg_ctlcluster` 不兼容
- **原因**：PG18 官方镜像改变了数据目录规范，要求挂载到 **`/var/lib/postgresql`**（不再是 `/var/lib/postgresql/data`），以支持 `pg_upgrade --link`
- **解决**：compose volumes 改为 `pgdata:/var/lib/postgresql`，并删除旧卷后重建
- **重建命令**：

```bash
docker compose down
docker volume rm knowhow_pgdata
docker compose up -d db
```

## 4. 常用运维命令

| 操作 | 命令 |
|---|---|
| 启动数据库 | `docker compose up -d db` |
| 停止数据库 | `docker compose down`（保留数据卷） |
| 完全重置（删数据） | `docker compose down && docker volume rm knowhow_pgdata` |
| 查看容器状态 | `docker ps --filter name=rag_db` |
| 查看日志 | `docker logs rag_db` |
| 进入 psql | `docker exec -it rag_db psql -U rag -d rag` |
| 健康检查 | `docker exec rag_db pg_isready -U rag -d rag` |
