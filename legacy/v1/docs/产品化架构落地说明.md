## 任务 #7：防腐层三件套（`app/providers/`）

| 接口 | 协议类 | 实现 | 切换 |
|---|---|---|---|
| `EmbeddingProvider` | `embed(texts)` | `LocalBgeM3Provider`（本地）<br>`ApiEmbeddingProvider`（OpenAI 兼容） | `EMBEDDING_BACKEND` |
| `LLMProvider` | `chat(messages)` | `DeepSeekProvider`<br>`GenericOpenAIProvider`（Qwen/GLM） | `LLM_PROVIDER` |
| `VectorStoreProvider` | `search/upsert` | `PgVectorProvider`（pgvector）<br>`LanceDBProvider`（多模态预留） | `VECTOR_STORE` |

**关键修复**：pgvector 0.5.1 + psycopg 3.3.6 的 `register_vector` 适配器未生效（list 被序列化成 `{...}` 而非 `[...]`），改用**向量文本直传**（`'[' + ','.join(f"{x:.8f}") + ']'`）作为 SQL 参数，检索恢复正常。

**验证**：faq id=1 检索 top3 → 自身 1.0、22 号 0.773、193 号 0.769。

## 任务 #10：管理台 API（`app/admin_api.py`）

**四角色 RBAC**
| 角色 | 能力 |
|---|---|
| `agent` 客服 | 只读检索问答，数据级仅 public+internal |
| `editor` 业务员 | 上传/编辑/打标（编辑后自动回 draft） |
| `reviewer` 审核员 | 审核流 approve/reject |
| `admin` 管理员 | 全部 + 批次管理 |

**数据级权限**：`permission IN (public, internal)` 客服；confidential 需 editor 以上。SQL 层过滤，防越权。

**接口清单**
- `GET /faq?status=&category=&q=`（数据级过滤）
- `GET /faq/{id}` / `PUT /faq/{id}`（编辑+version 递增）
- `POST /faq/{id}/tags`（5 维打标）
- `POST /faq/{id}/approve|reject`（审核流）
- `GET /batches` / `GET /health`

**启动**：`uv run uvicorn app.admin_api:app --port 8000`
**验证**（X-User-Id 头模拟）：客服编辑 403 / 业务员编辑 200 / 审核员通过 200 / 业务员审核 403 / 客服查 confidential 404。

## 2026-10-28 更新：产品形态决策（双出口架构 + 角色化前台）

> 决策背景：产品面向三类使用者——公司负责人（管理/查看/决策）、新人员工（培训/上手）、业务员工（客服/业务使用）。
> 核心结论：**一个知识内核 + 两个能力出口 + 三个角色视图**，不采用"管理后台 + 客服系统"的简单二分。

### 1. 能力出口决策：内部 Agent 优先，MCP Server 叠加

**结论**：不是二选一，是"一套内核、两个出口"；优先级内部 Agent 先行（闭环即壁垒），MCP 作为分发通道低成本叠加。

| 维度 | 内部 Agent（先行） | MCP Server（叠加） |
|---|---|---|
| 谁编排/谁体验 | 自己（可控） | 外部 Agent（codex/Claude/Cursor） |
| 价值归属 | 闭环沉淀给自己 | 能力借出，上层 Agent 分走一半感知 |
| 壁垒来源 | 业务闭环 + 数据飞轮 | 知识资产 + 评测质量（协议本身无壁垒） |
| 实现成本 | 中（UI/编排/反馈） | 低（复用现有 API + 一层工具封装） |
| 适用场景 | 客服生产系统、员工日常 | 开发/办公 Agent 集成、生态分发 |

**为什么内部 Agent 是护城河**：knowhow 的核心资产是"问答 → 审计 → 人工反馈 → 知识更新 → 评测门禁"闭环飞轮（黄金集 + Recall≥0.9 门禁 + 审计日志）。这个飞轮只能长在自己拥有的 Agent 里——MCP 形态下外部 Agent 用了知识但不回馈，飞轮转不起来。且外贸知识（价格/交期/认证红线）敏感，内部闭环保证"知识不出内网"。

**为什么 MCP 仍值得做**：检索层已是 provider 防腐层（embedding/llm/vector_store 可插拔），再加一层 MCP 工具层（`knowledge_search` / `knowledge_ask` / `knowledge_feedback`）复用现有 API，一个迭代完成，换来"企业知识成为团队 AI 工具的公共基础设施"。商业上是增值集成，不是主交付物。

**落地路径**：
1. 先做：客服问答工作台（内部 Agent 第一界面：检索+生成+红线拦截+反馈按钮），跑通飞轮
2. 再做：MCP Server（stdio 起步 → streamable HTTP），工具挂 RBAC + 审计
3. 架构约束：两者共享同一 `knowledge-service` 内核接口，MCP 不直连数据库；MCP 默认只开放 public+internal 权限域，红线知识不对外部 Agent 暴露

### 2. 产品形态：一个平台、按角色分视图

不是"管理后台 + 客服系统"两分，而是三视图 + 一内核：

```
┌────────────────────────────────────────────────┐
│  统一登录（账号密码 + 角色 RBAC，已有）           │
├──────────┬──────────┬──────────┬───────────────┤
│ ① 管理后台  │ ② 员工门户  │ ③ 客服工作台   │（MCP 出口）
│ 负责人/管理员 │ 全员/新人   │ 客服/业务员   │ 外部 Agent
│ · 数据驾驶舱  │ · 知识浏览  │ · 客户问答助手  │
│  知识量/质量/ │  分类/搜索  │  检索+生成+红线  │
│  使用量/评测  │ · 培训模式  │ · 反馈按钮      │
│ · 数据入录   │  学习路径/  │ · 会话审计      │
│ · 知识卡管理  │  练习问答  │                 │
│ · 评测/审计  │ · 个人收藏/ │                 │
│ · 权限分级   │  最近使用  │                 │
└──────────┴──────────┴──────────┴───────────────┘
                 共享内核（PG+pgvector / 权限 / 审计 / 评测飞轮）
```

**视图拆分依据（按岗位职责，不按功能堆叠）**：
- **负责人视图（/admin 已有）**：关心"数据好不好、用得怎么样"——驾驶舱补三块：知识资产总览（知识卡数/覆盖模块/版本分布）、质量态势（评测趋势/召回审计/红线）、使用数据（问答量/命中率/反馈率）。现有 7 菜单项足够，新增"驾驶舱"为首屏。
- **员工门户（新）**：全员可用的知识入口——按模块浏览知识卡（产品参数/报价话术/认证/物流…）、全文+语义搜索、新人培训模式（引导式学习路径：按模块顺序阅读 + 练习问答打分）。定位"知识即培训"，替代传统培训 PPT。
- **客服工作台（新）**：客服/业务员的问答生产工具——输入客户问题（支持粘贴英文原问）→ 检索 → 生成应答（带知识卡引用）→ 红线拦截提醒 → 人工采纳/编辑后发送 → 反馈回流（答得好/差，触发知识更新工单）。这是飞轮的起点，也是 MCP 之前要跑通闭环的产品。

**实现形态建议（保持单体，不微服务）**：
- 同一 FastAPI 应用，路由按视图分：`/admin`（负责人）、`/workspace`（员工门户）、`/agent`（客服工作台）
- 登录后按角色落默认视图：admin/reviewer → /admin；editor → /workspace + /agent；agent → /agent
- 复用现有页面资产：admin.html 的侧边菜单布局可直接作为三视图的共用壳（按角色裁剪菜单项）
- 内核接口先行：`knowledge-service` 统一检索/问答/反馈三个原语，三视图 + MCP 都调它

### 3. 执行计划（下一步任务拆分）

| 任务 | 内容 | 优先级 |
|---|---|---|
| A. knowledge-service 内核层 | 检索/问答/反馈三原语 + 权限 + 审计统一出口 | P0（先于一切 UI） |
| B. 客服工作台 /agent | 检索+生成+红线拦截+反馈回流，跑通飞轮 | P0 |
| C. 员工门户 /workspace | 知识浏览/搜索/培训模式（学习路径+练习） | P1 |
| D. 负责人驾驶舱 | 知识资产/质量态势/使用数据三块总览 | P1 |
| E. MCP Server | knowledge_search/ask/feedback 工具 + RBAC/审计 + codex 接入验证 | P2 |
