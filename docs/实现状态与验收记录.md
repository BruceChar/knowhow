## 1. 当前结论

P0 可用性与安全阻断项已完成；P1 的知识发布、Import Studio、产品/变体/
报价导入已形成可运行闭环；P2 的客服辅助、事实调用、反馈回执、反馈结果查看、
知识回流和审计已形成闭环。员工培训门户、驾驶舱、多租户、异步大文件任务和
MCP 仍未实现。

系统现在的准确对外定义是：**可试点的企业知识治理与客服辅助 MVP**，不是
已经完成客户验收的全渠道 AI 客服平台。

## 2. 已实现

### 2.1 可用性与安全

- `src/main.py` 与 `src.api.admin_api:app` 使用同一应用入口。
- 未登录 API 默认拒绝；`X-User-Id` 仅在 `KNOWHOW_DEV_AUTH=1` 时可用。
- 用户、角色来自数据库，不再使用内存角色表。
- Session 只保存 token 的 SHA-256 指纹；Cookie 是 HttpOnly + SameSite=Lax。
- Cookie 写请求要求 `X-Knowhow-CSRF: 1` 并校验 Origin。
- 新建用户返回一次性初始密码，并强制首次改密。
- Dockerfile、compose、README 和环境变量示例与 `src/` 目录一致。
- 迁移使用 `schema_migration` 账本和 SHA-256 校验；已执行迁移不会被重复执行。

### 2.2 知识版本与发布

- FAQ 编辑会保留当前 `published_snapshot`，线上版本在审核期间不中断。
- 审核通过后原子切换发布快照、发布 embedding 和版本号。
- 旧版本保存在 `faq_version`，状态为 `superseded`。
- 生产检索读取 `active_faq`，过滤有效期、权限和 `customer_ready`。
- 客户可发送性和内部可见性已拆成 `customer_ready` 与 `permission`。

### 2.3 Import Studio 与 ETL

- `src/ingest/studio.py` 支持 XLSX/XLS/CSV/JSON/DOCX 的结构识别。
- 业务人员可选择工作表，把源列映射到目标字段，无需写 YAML、SQL 或 Python。
- 声明式转换支持 trim、大小写、去空格、数字/整数、日期、币种、列表和布尔值。
- 产品导入可生成 `sku`、`variant` 和可选 `offer` 草稿。
- 报价缺少币种或有效期时预检失败，不会把不完整价格写入正式事实层。
- 模板优先从数据库读取，YAML 仅作为种子/离线兜底。
- 模板保存到 `mapping_config_version`；导入批次同时记录 `mapping_id` 和
  `mapping_version_id`。
- 导入批次记录源文件 SHA-256、原始行、规范化结果和统计。

### 2.4 产品、事实与客服

- 产品和报价有独立审核/驳回接口；“产品与报价”页面完成审核操作。
- 发布新报价时，同变体旧的已批准报价原子改为 expired，避免多个当前价。
- 报价事实工具只读取已批准、有效且所属 SKU 已批准的快照。
- `/v1/ask` 串联检索、门禁、实时事实、草稿生成和审计。
- 没有客户可用知识时不冒充回答；需要动态事实但缺少 SKU 或报价时升级人工。
- 缺少远程 LLM 密钥时，使用仅基于知识卡和工具结果的可追溯抽取式草稿；
  设置 `LLM_REQUIRED=1` 可关闭该降级路径。
- `/agent` 提供客服辅助页面，展示动作级、引用、工具结果和审计编号。
- 反馈使用独立 `agent.feedback` 权限；提交后立即返回问题单/知识卡处理结果。
- `audit_log` 记录反馈人、反馈时间与判断；错误/待复核反馈幂等进入 `issue`。
- 反馈区分“标准答案”和“改进建议”：前者强制填写答案，后者允许只提交建议。
- 审核员可将标准答案采纳为 FAQ 待审核版本，或将建议采纳为回答规则。
- 标准答案默认使用“客户原问题 + 标准答案”新建 FAQ，避免覆盖错误的引用知识；
  审核员仅在问题确实对应时可显式选择修订引用 FAQ。
- 回答规则独立存储于 `answer_policy`，用于语言、格式和澄清顺序，不承载业务事实。
- 自由文本规则会注入 LLM 系统提示；离线模式对“中文问题 + 英文依据”执行模板保护，
  改为中文人工升级提示，不再输出英文泛化草稿。
- 语言保护会把动作级强制提升到 C，并标记 `needs_human_review=true`。
- “反馈闭环”页面展示反馈覆盖率、正确/错误数量、待处理数和已反哺知识数。
- 普通客服仅查看自己的反馈；审核员可查看全量队列并采纳或拒绝。
- 采纳修正会创建或更新 FAQ 草稿版本；不绕过审核，不直接修改线上发布快照。
- 反馈结果、处理结论、关联 FAQ/版本和审核人均持久化并可再次查看。

### 2.5 评测

- 已有 Recall@5、Precision@5、MRR@5、事实命中代理和红线门禁。
- 评测报告区分 `dev` 与 `production` 模式并持久化历史。
- 生产门禁只允许已发布快照参与检索。

`node --check`。

### 3.2 数据库迁移

- 首次执行应用 `migration_v2.sql` 至 `migration_v5.sql`。
- 第二次执行输出 `migrations applied: none pending`。
- 迁移不再 `TRUNCATE sessions`，重复执行不会踢掉所有登录用户。

### 3.3 真实 HTTP 闭环

使用临时 CSV 完成：

```text
上传 → 自动字段建议 → 预检 1 行 / 0 错误 → 写入 SKU/Variant/Offer 草稿
→ 产品审核 → 报价发布 → 客服价格提问 → 返回 B 级事实草稿
→ 反馈写入审计
```

本次反馈专项使用真实登录和 HTTP 请求完成：

```text
问答审计 → 提交“需要修正”反馈 → 返回待处理问题单
→ 反馈结果接口可查看 → 审核员采纳 → 关联 FAQ 生成 v+1 待审核草稿
→ 汇总接口反映已反哺 1 条
```

验收后已删除本次临时审计/问题单，并从发布快照恢复被验收修改的 FAQ。

标准答案与建议分流另用真实 HTTP 验证：

```text
“牵引绳有哪些” → 中文问题/英文依据保护 → C 级人工复核
仅改进建议 → 采纳为 language_mirror 回答规则 → 规则立即生效
标准答案 → 采纳为 FAQ 待审核版本
```

验收后已删除本轮测试审计、问题单、回答规则，并恢复 FAQ 发布快照。

价格问答实际返回：

```text
MOQ：100；交期：15；报价有效至：2026-12-31
此价格来自已审批报价快照，发送客户前请由业务员确认。
[来源: 报价事实 OFFER-...]
```

测试结束后，临时 SKU、变体、报价、导入批次、审计和问题单均已删除。

## 4. 尚未完成

1. 402 条 FAQ 已可用于客服检索；仍需用真实客服问题持续校验回答质量。
2. 1,458 条 SKU 仍是草稿；正式变体与报价需要从报价单按模板导入并审核。
3. 导入暂为同步、全批次预检；问题行可查看，但不能在页面逐行修正后局部重跑。
4. 尚缺 SOP/政策/PDF 等通用知识模板和 Evidence 原文件片段化管理。
5. 评测主要是 FAQ 检索；产品事实、引用支持率、动作正确率和真实客服效果尚未纳入黄金集。
6. 当前是单企业单库。多租户需要 `tenant_id`、RLS、跨租户隔离测试。
7. 客服页面完成单轮辅助，不包含完整会话、工单、CRM 和全渠道发送。
8. MCP、员工培训门户、驾驶舱和异步任务队列仍属于路线图。
9. 反馈闭环当前到“生成待审核知识版本/生效回答规则”为止，知识发布仍由审核流程控制。
10. 任意自由文本规则的离线执行尚未覆盖；当前只有语言一致性具备确定性模板，
    其他规则在未配置 LLM 时作为人工审核约束保留。
11. 回答规则目前统一作用于全部查询；按产品品类、渠道或客户语言细分仍需扩展。

## 5. 下一批验收顺序

1. 从真实报价单导入少量代表性 SKU、变体和报价，完成产品→报价→客服事实验收。
2. 跑 production 评测并形成最新发布门禁报告。
3. 补问题行局部修正和重跑，降低业务人员处理大表的成本。
4. 建立 SOP/政策模板与 Evidence 定位，再扩充证据和权限评测。
5. 若真实建议中大量是通用表达问题，再接入 LLM 做“建议分类 + 候选改写”，
   但候选必须人工确认，事实答案不得由建议自动生成。
6. 引入真实客服反馈数据后，再评估培训门户、驾驶舱和外部 Agent/MCP。
