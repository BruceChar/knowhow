# Knowhow V2 产品蓝图

> 2026-10-31 · 面向中小外贸企业的销售知识与 AI 工作系统

## 1. 产品定义

Knowhow 不是管理型知识库，而是把优秀业务员经验沉淀为公司能力的工作系统。

产品价值：

```text
业务价值
= 客户交互量 × 草稿采用率 × 单次节省时间 × 回答正确率
- 错误承诺与返工成本
```

组织能力：

```text
知识留存率
= 高频客户问题中，有已审核答案且能被直接复用的比例
```

## 2. 用户与核心任务

| 用户 | 核心任务 |
|---|---|
| 老板 | 看见知识缺口、新人进度、风险回答和真实采用情况 |
| 业务员 | 快速得到有依据、可编辑、符合语言和公司规则的回复 |
| 知识负责人 | 只处理异常、冲突、过期和高风险知识 |
| 新人 | 用公司的真实客户问题练习，直到能独立接待 |

## 3. 设计原则

1. 价值发生在客户交互现场，不在管理后台。
2. 知识是工作过程的副产品，不要求员工额外大量写文档。
3. 价格、交期、认证等业务事实优先于模型生成。
4. AI 负责理解、检索和起草；人负责承诺、风险判断和最终发送。
5. 部署和维护成本也是产品体验。
6. 衡量业务结果，不用知识卡数量自我感动。

## 4. 核心闭环

```text
公司资料 / 标准问答 / 真实客户问题
                 ↓
        草稿、确认、发布
                 ↓
客户问题 → 检索 + 规则 + 事实 → AI 草稿
                 ↓
业务员编辑 / 复制 / 标记已发送
                 ↓
记录最终答案、修改差异和未解决问题
                 ↓
知识缺口 / 冲突 / 过期 → 负责人处理
                 ↓
更新知识、回答规则和新人训练题
```

## 5. 产品信息架构

| 工作区 | 解决的问题 |
|---|---|
| 今日工作台 | 今天有哪些知识缺口、风险和待办 |
| 销售工作台 | 客户问题如何变成可发送答案 |
| 公司知识 | 产品、FAQ、SOP、政策和案例在哪里 |
| 待处理 | 哪些问题需要负责人决策 |
| 团队与新人 | 团队是否可上岗，谁需要训练 |
| 经营看板 | 系统是否节省时间、减少错误和留住能力 |

## 6. 知识类型

- `faq`：标准客户问答。
- `product`：产品事实与规格。
- `policy`：品牌、报价、承诺、语言和风险规则。
- `playbook`：客户异议、跟进、报价等场景步骤。
- `case`：真实客户问答案例。
- `sop`：内部操作流程。

每份知识必须有来源、负责人、风险级别、状态和有效期。

## 7. 成功标准

首个客户试点达到：

- 80% 的 Top 50 客户问题有已发布答案。
- AI 草稿采用或少量修改后采用率 ≥ 60%。
- 业务员平均首次回复准备时间下降 30%。
- 新人独立处理高频问题的比例两周内 ≥ 60%。
- 高风险问题 100% 进入人工确认，不直接承诺。
- 所有知识修改和客户回复均可追溯。
