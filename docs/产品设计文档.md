## 1. 产品概述

### 1.1 背景

外贸中小企业的知识资产（产品参数、报价话术、认证物流、客户应对）大量散落在业务员的微信聊天、Excel、PPT 里。新人上手靠老员工口传，客服回答靠个人经验，负责人看不到 "知识资产值多少钱、质量好不好、谁在用"。

### 1.2 产品定位

一套本地部署的企业知识库系统：**采集原始数据 → 结构化知识卡 → 审核发布 → 检索问答 / 学习使用 → 反馈迭代 → 评测把关**，覆盖管理、培训、业务三条使用线。

### 1.3 核心价值



| 使用者      | 价值                                   |
| -------- | ------------------------------------ |
| 公司负责人    | 看得到知识资产规模、质量走势、使用情况；拍板 "补什么知识、改什么话术" |
| 新人员工     | 不用等老员工口传，按学习路径自学 + 练习，快速上手           |
| 客服 / 业务员 | 客户问题即时检索生成应答（带依据、守红线），答完反馈沉淀         |
| 企业整体     | 知识 "人人可贡献、审核后发布"，不依赖个人记忆力，人走知识留      |

## 2. 用户与角色

### 2.1 权限模型（动态角色 + 页面/功能权限树，v1.1 已落地）

**模型**：账户（system_account）→ 角色（system_role，可自建）→ 权限点（system_permission，模块→页面→功能树）。系统表统一 `system_` 前缀；权限按「模块 → 页面 → 功能」三级勾选分配，管理界面即看即配。

**系统默认账户（仅两个，入库）**：

| 账户 | 密码 | 绑定角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `admin` | 管理员 | 全部权限，可管理角色/账户/数据治理 |
| `editor` | `editor` | 业务员 | 知识编辑/入录/共建（无审核/评测/系统管理） |

生产环境（`KNOWHOW_PROD=1`）种子密码随机生成并强制首登改密；也可用 `SEED_PASSWORDS=admin=xxx,editor=xxx` 注入强密码。

**内置角色（权限模板，不可删，可复制改造成新角色）**：

| 角色 | 代表 | 权限点模板 | 数据范围 |
| --- | --- | --- | --- |
| `admin` 管理员 | 负责人 / IT | 全部 22 个权限点 | full（含保密） |
| `reviewer` 审核员 | 主管 / 资深业务 | 审核/打标/评测/审计 17 点 | full |
| `editor` 业务员 | 业务员 / 产品助理 | 编辑/入录/共建 12 点 | full |
| `agent` 客服 | 一线客服 / 跟单 | 只读检索/问答/提建议 5 点 | standard（public+internal） |

**权限点树（22 点，v1.1 已落地）**：数据管理（数据入录：查看/上传/执行）、知识管理（知识卡：查看/编辑/审核/下线；建议单：查看/提交/处理）、质量保障（评测：查看/运行；召回审计；红线案例；问答日志）、系统管理（驾驶舱；账户管理；角色与权限）、员工门户（知识浏览；学习培训）、客服工作台（客户问答；问答反馈）。自定义角色可任意勾选组合；`data_scope` 控制数据可见域（standard=public+internal / full=全部）。

### 2.2 权限设计核心：**"贡献权下沉 + 审核权保留"**



* **全员可贡献**：客服、业务员都能提交 "知识建议"（新问题、过时参数、新话术），人人都是知识来源；

* **编辑分级**：绑定 `editor` 及以上（或勾选 faq.edit）可直接改草稿知识卡、上传原始数据（xlsx/json/docx）；

* **审核保留**：任何变更（新建议、编辑、重新入录）都必须经 `reviewer` 权限（faq.review）审核才进入 "已发布"，防止低质量 / 错误知识污染生产；

* **红线特殊**：价格、交期、认证承诺类知识，只有 `faq.review` 可改，且改后强制过评测门禁；

* **权限隔离**：后端每个端点按权限点校验（require_permission），前端菜单按权限点显隐；数据级按角色 data_scope 生成 SQL 过滤，防越权读保密数据。

* 详见 [§5 权限矩阵](#5-权限与安全模型)。

## 3. 产品形态：三视图一内核

一个平台、三个按角色裁剪的视图、一个共享内核。不采用 "管理后台 + 客服系统" 两分 —— 因为培训、共建、驾驶舱都不是单纯 "管" 或 "用" 能覆盖的。



```
┌──────────────────────────────────────────────────────┐
│                统一登录 · 账号密码 + Cookie 会话       │
├──────────────┬──────────────┬──────────────┬─────────┤
│ ① 管理后台    │ ② 员工门户    │ ③ 客服工作台  │ MCP 出口 │
│ /admin       │ /workspace   │ /agent       │（P2）   │
│ 负责人/管理员 │ 全员/新人     │ 客服/业务员   │ codex/  │
│              │              │              │ Claude  │
│ 驾驶舱        │ 知识浏览      │ 客户问答      │         │
│ 入录/知识卡   │ 学习路径+练习 │ 检索+生成     │ knowledge│
│ 评测/审计     │ 建议提交      │ 红线拦截      │ _search  │
│ 权限/数据治理 │ 收藏/最近     │ 反馈回流      │ _ask     │
└──────────────┴──────────────┴──────────────┴─────────┘
       共享内核 knowledge-service
  （检索/问答/反馈/建议 原语 + RBAC + 审计 + 评测门禁）
  （PG+pgvector · 本地 embedding · 数据不出内网）
```

**登录后默认落地视图**：`admin`/`reviewer` → `/admin`；`editor` → `/workspace`（+ 可切 `/agent`）；`agent` → `/agent`。三者同一套壳（侧边菜单），菜单项按角色裁剪。

## 4. 核心业务流

### 4.1 知识生命周期（含员工共建）



```
[贡献]                        [审核]            [发布]      [使用]          [迭代]
全员提交建议 ──┐
员工编辑草稿 ──┤──> 建议/草稿队列 ──> reviewer ──> 已发布 ──> 检索问答       ──┐
数据入录批次 ──┘     (draft)       通过/驳回      (approved)  员工门户学习     │
                                                                           │ 反馈
                驳回 → 退回贡献者补充/丢弃                   质量变差/缺口 ──┘
                                                           → 生成更新工单 → 回到贡献
```

关键规则：



* **建议单（**`knowledge_suggestion`**）**：全员可建。字段：问题（客户原话 / 场景）、期望答案、来源依据（聊天截图 / 邮件 / 报价单）、建议模块。提交后自动进 `reviewer` 队列，可 "采纳并建卡 / 采纳并入现有卡 / 驳回"。

* **草稿编辑**：`editor` 编辑已发布卡 → 版本 +1 → 状态回 `draft` → 重新审核。历史版本留档可回滚。

* **数据入录**：原始文件（产品图鉴 xlsx、话术 json…）上传留档（`raw_data`），ETL 配置化映射入库，问题行审计。换企业 = 换映射配置，代码零改动。

* **红线保护**：`risk_level=high`（价格 / 交期 / 认证承诺）的知识卡，仅 `reviewer`+ 可改；改后必须触发评测回归。

### 4.2 客服问答闭环（飞轮，产品护城河）



```
客户问题（可粘贴英文原问）
   → 向量检索 Top-K（限用户可见域）
   → LLM 生成应答（引用知识卡 ID + 红线前置校验）
   → 人工采纳/编辑后发送（客服工作台）
   → 反馈回流：命中好/差 / 无命中
   → 差评 & 无命中自动生成"知识建议单"（回到生命周期起点）
```

飞轮意义：**客户流量进来，质量反馈沉淀，知识持续变好。** 这是内部 Agent 优先于 MCP 的根本原因 ——MCP 出口拿不到反馈，飞轮转不起来。

### 4.3 培训学习流



```
新人登录 /workspace
  → 学习路径（按模块：产品参数→报价逻辑→认证→物流→客户应对）
  → 逐节阅读知识卡 → 练习问答（系统出题，即时打分）
  → 模块结业测试（正确率 ≥80% 过关）
  → 日常：语义搜索 + 收藏 + 最近使用
```

### 4.4 负责人决策流



```
驾驶舱首屏（/admin）
  知识资产：知识卡数/模块覆盖/版本分布/贡献榜（可选 P2）
  质量态势：评测趋势/召回审计/红线告警
  使用数据：问答量/命中率/反馈率/无命中 Top 问题
  → 点击钻取 → 直接下指令（指派建议单/发起评测/改权限）
```

## 5. 权限与安全模型

### 5.1 角色 × 能力矩阵



| 能力                    | agent 客服 | editor 业务员 | reviewer 审核员 | admin 管理员 |
| --------------------- | -------- | ---------- | ------------ | --------- |
| 检索问答（public+internal） | ✅        | ✅          | ✅            | ✅         |
| 浏览全部知识库               |          | ✅          | ✅            | ✅         |
| 提交知识建议（共建）            | ✅        | ✅          | ✅            | ✅         |
| 编辑草稿 / 打标             |          | ✅          | ✅            | ✅         |
| 入录原始数据                |          | ✅          | ✅            | ✅         |
| 审核发布（通过 / 驳回）         |          |            | ✅            | ✅         |
| 修改红线知识（high）          |          |            | ✅            | ✅         |
| 运行评测 / 查看审计           |          |            | ✅            | ✅         |
| 用户 / 角色管理             |          |            |              | ✅         |
| 数据治理（红线配置 / 归档 / 删除）  |          |            |              | ✅         |

### 5.2 数据可见域（行级过滤）



| 可见域            | 含义                | 可访问角色              |
| -------------- | ----------------- | ------------------ |
| `public`       | 全员可见（基础产品知识）      | 所有角色               |
| `internal`     | 内部经营知识（报价逻辑、客户应对） | 所有登录用户（对外 MCP 不开放） |
| `confidential` | 敏感（成本、利润、大客户策略）   | `editor`+          |

### 5.3 安全基线



* 认证：账号密码 + pbkdf2 哈希 + httpOnly Cookie 会话（防 XSS 窃取）+ 登录限流（5 次锁 10 分钟）+ 强制首登改密

* 审计：所有读 / 写 / 审核 / 评测动作落 `audit_log`，可追溯

* 红线：`risk_level=high` 知识在生成环节前置校验，命中即拦截 / 降级，绝不外泄给 MCP

* 数据主权：全量数据本地 PostgreSQL，模型本地加载；对外仅 MCP 受控工具

## 6. 功能规格

### 6.1 管理后台 /admin（已有 7 菜单，新增驾驶舱）



| 菜单                 | 功能要点                                | 状态   |
| ------------------ | ----------------------------------- | ---- |
| 驾驶舱（新增）            | 知识资产 / 质量态势 / 使用数据三块总览 + 钻取         | 规划   |
| 数据入录               | 上传原始文件 → 批次入录 → 问题行审计               | ✅ 已有 |
| 知识卡管理              | 列表 / 筛选 / 搜索、详情 / 打标（5+1 维）、通过 / 驳回 | ✅ 已有 |
| 建议单管理（新增）          | 全员建议队列：采纳建卡 / 并入 / 驳回               | 规划   |
| 评测总览               | KPI、评测触发、趋势                         | ✅ 已有 |
| 召回审计 / 红线案例 / 问答日志 | 三层评测明细                              | ✅ 已有 |
| 权限分级               | 用户 CRUD、角色调整                        | ✅ 已有 |

### 6.2 员工门户 /workspace（新）



* **知识浏览**：按模块分类（产品 / 报价 / 认证 / 物流 / 客户应对）浏览知识卡；语义搜索 + 筛选（模块 / 风险级 / 标签）

* **学习路径**：预置模块化学习路径，逐节阅读 + 练习问答 + 结业测试；个人进度持久化

* **知识建议**：任意页面 "提建议" 入口（问题场景 + 期望答案 + 依据），可附文件

* **个人空间**：收藏、最近使用、我的建议（状态跟踪）

### 6.3 客服工作台 /agent（新）



* 输入区：客户问题输入（支持英文原问粘贴）

* 应答区：LLM 生成应答 + 引用的知识卡（可查看原文）+ 红线拦截提示

* 操作：采纳发送 / 编辑后发送 / 重生成 / 标记无效

* 反馈：答案 "有帮助 / 无帮助 / 未命中"，一键生成建议单

* 会话历史：最近会话、审计追溯

### 6.4 MCP 出口（P2，叠加）



| 工具                                 | 说明               | 权限域             |
| ---------------------------------- | ---------------- | --------------- |
| `knowledge_search(q, top_k)`       | 向量检索返回知识卡片段 + 引用 | public+internal |
| `knowledge_ask(q)`                 | 检索 + 生成完整应答      | public+internal |
| `knowledge_feedback(q, helpful)`   | 反馈回流（推动知识迭代）     | 登录用户            |
| `knowledge_submit_suggestion(...)` | 提交建议单            | 登录用户            |

约束：MCP 不直连数据库；不开放 `confidential` 与红线知识；全部调用落审计。

## 7. 技术架构

### 7.1 分层



```
┌─ 表现层（同一 FastAPI 应用，路由分视图）
│   /admin（admin.html） · /workspace · /agent
├─ 内核层 knowledge-service（三视图 + MCP 共用的唯一出口）
│   search / ask / suggest / feedback + 权限 + 审计
├─ 领域层
│   ingest（ETL 配置化）· eval（评测门禁）· faq（知识卡）· auth（认证 RBAC）
├─ 防腐层 providers（面向接口，可插拔）
│   embedding_provider · llm_provider · vector_store_provider
└─ 存储
    PostgreSQL 16/18（业务表 + pgvector 向量 + 审计）· 本地模型 data/models
```

### 7.2 选型



| 层   | 选型                                | 理由                          |
| --- | --------------------------------- | --------------------------- |
| 后端  | Python 3.12 + FastAPI + uvicorn   | 现有代码基础；评测 / ETL 生态成熟        |
| 存储  | PostgreSQL + pgvector             | 业务与向量同库，事务一致，免维护 ES / 专用向量库 |
| 向量  | 本地 bge-m3（可换 Qwen3-Embedding）     | 数据不出内网，性能满足中小团队             |
| LLM | API（OpenAI 兼容可插拔）                 | 生成质量优先；防腐层可换本地模型            |
| 前端  | 原生 HTML/JS 单页（无构建）                | 中小团队免工程化成本；沿用 admin.html    |
| 部署  | 单机 Docker（PG）+ launchd/systemd 常驻 | 覆盖 <50 人团队，不引入微服务复杂度        |

### 7.3 演进约束



* 新增能力一律进 `knowledge-service`，表现层与 MCP 不直接触碰领域对象

* provider 防腐层保证 embedding/LLM/ 向量库任一可替换，业务代码零改动

* 保持单体；仅当评测 / 入录成为独立异步工作负载时再评估任务队列

* 一切变更关联 `audit_log`（谁、何时、为何）

## 9. API 与 MCP 设计

### 9.1 核心 REST API（在现有基础上新增）



```
认证    POST /auth/login · /auth/logout · GET /auth/me · POST /auth/password
```

### 9.2 MCP Server（P2）



* 传输：stdio 起步（codex/Claude Desktop 即插即用）→ 后续 streamable HTTP

* 工具：`knowledge_search` / `knowledge_ask` / `knowledge_feedback` / `knowledge_submit_suggestion`（schema 见 6.4）

* 鉴权：工具调用需携带会话（OAuth 或项目 token），按 RBAC 过滤可见域

* 红线：`risk_level=high` 与 `confidential` 域在 MCP 层硬编码不返回

## 10. 质量保障体系

### 10.1 三层评测（已落地）



| 层   | 指标                             | 门禁                       |
| --- | ------------------------------ | ------------------------ |
| 检索层 | Recall@5 / Precision@5 / MRR@5 | Recall ≥ 0.9 · MRR ≥ 0.5 |
| 事实层 | 事实正确率（黄金集标注 vs 生成答案）           | ≥ 0.9                    |
| 红线层 | 红线错误率                          | = 0                      |

### 10.2 黄金集（已落地）



* 57 条 × 35 模块（含 `ideal_hit_questions` 多解），覆盖主要客户问题

* 每次知识变更 / 入录后触发回归评测，门禁不过不允许发布

* 评测报告持久化 + 后台可视（KPI / 趋势 / 召回审计 / 红线案例 / 问答日志）

### 10.3 反馈驱动的知识迭代



* 客服反馈（有帮助 / 无帮助 / 未命中）自动关联知识卡

* "无命中" 直接生成建议单 → 进入生命周期 → 扩充黄金集 → 回归

## 13. 决策记录与开放问题

### 已决策



| 决策              | 结论                                      | 理由                                  |
| --------------- | --------------------------------------- | ----------------------------------- |
| 内部 Agent vs MCP | 内部优先，MCP 叠加                             | 闭环飞轮是壁垒；MCP 是低成本分发                  |
| 产品形态            | 三视图一内核（非管理后台 + 客服二分）                    | 按岗位职责组织，培训 / 共建 / 驾驶舱都不是纯 "管" 或 "用" |
| 共建权限            | 贡献权下沉全员 + 审核权保留 reviewer                | 保证知识质量，避免错误知识污染生产                   |
| 技术栈             | 单体 FastAPI + PG/pgvector + 本地 embedding | 中小团队免运维复杂度，数据不出内网                   |
| 红线              | high 风险知识 reviewer+ 可改，改后强制评测回归         | 价格 / 交期 / 认证承诺是外贸高风险                |

### 开放问题（需业务侧确认）



1. **培训考核是否需对接公司 HR / 绩效**（如结业分数进绩效）—— 影响 learning\_progress 是否需要导出 / 对接

2. **贡献激励**：是否做 "贡献榜 / 积分"（P2 可选），还是先用管理员指派

3. **多语言**：客服问答是否需输出目标语言（英语 / 西语等）的正式客户应答模板，还是仅内部中文

4. **数据规模**：当前 1458 SKU / 401 话术；若接入更多企业数据源（海关数据、询盘记录），是否需要扩展入录映射数量
