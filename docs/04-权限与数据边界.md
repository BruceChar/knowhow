# Knowhow V2 权限与数据边界

## 1. 为什么不能只做角色名称

“业务员”这个角色并不能说明：

- 能否看到成本、利润和大客户信息。
- 能否看到另一个销售团队的报价。
- 能否发布知识，还是只能提交建议。
- 能否下载原始报价单、邮件和客户资料。

因此权限必须同时覆盖“功能权限”和“数据范围”。

## 2. 两层模型

### 功能权限

控制用户能执行什么动作：

| 权限 | 作用 |
|---|---|
| `ask.use` | 使用销售问答 |
| `knowledge.view` | 查看可见知识 |
| `knowledge.suggest` | 提交知识建议或草稿 |
| `knowledge.edit` | 编辑知识 |
| `knowledge.publish` | 发布和归档知识 |
| `gap.manage` | 处理知识缺口 |
| `dashboard.view` | 查看经营工作台 |
| `team.manage` | 添加、停用成员 |
| `role.manage` | 管理角色和权限模板 |
| `data.all` | 跨团队查看全部数据 |

### 数据范围

每条知识、证据和后续文件都必须有：

- `organization`：全公司可见。
- `team`：指定团队可见。
- `private`：仅负责人或明确授权用户可见。

业务员只能看到：

```text
organization 知识
+ 自己所属 team 的知识
+ 自己的 private 知识
```

老板、管理员或拥有 `data.all` 的角色可以跨团队查看。

## 3. 默认角色

系统提供四个可修改的模板，而不是让老板一开始配置几十个权限点：

| 角色 | 默认能力 | 默认数据范围 |
|---|---|---|
| 老板 | 全部权限 | 全公司 |
| 管理员 | 除企业所有权外的系统管理 | 全公司 |
| 知识负责人 | 查看、编辑、发布、处理缺口、看板 | 全公司 |
| 业务员 | 问答、查看、提交草稿 | 公司 + 本团队 |

老板可以复制模板，创建“某产品线业务员”“财务只读”“客服主管”等角色。

## 4. 文件与证据

原始文件不单独设置一套复杂权限，而是继承所关联知识的可见范围；也可设置比知识更严格的级别。

- 产品公开资料：公司范围。
- 客户聊天、邮件：团队范围。
- 成本表、利润表、客户名单：私有或指定角色。
- 下载行为同样受权限控制并记录审计。

## 4.1 多团队权限合并规则

一个成员可以属于多个团队，但只有一份公司角色。团队只记录成员关系和组长标记。
例如：

```text
张三：
  公司角色 = 业务员
  A 组身份 = 组长
  B 组身份 = 普通组员
```

处理规则：

1. **数据可见范围取并集**：张三可看公司知识、A 组知识、B 组知识和自己的私有知识。
2. **基础功能权限只看公司角色**：张三是否为其他团队组长，不会改变他的公司角色。
3. **组长是团队级例外**：仅在 A 组内增加编辑、发布和管理成员能力；B 组不继承该能力。
4. **公司级动作使用公司角色**：不能因为张三在 A 组是组长，就获得公司级角色管理、跨团队管理或全公司发布权限。
5. **私有知识不因组长身份扩大**：组长不能查看其他成员的私有知识。
6. **当前没有显式拒绝规则**：未来若增加 deny，必须遵循 deny 优先。
7. **高风险规则不能被组长身份覆盖**：价格、认证、赔付等红线仍由公司规则和事实层控制。

## 4.2 组长权限

“组长”是团队成员上的团队级标记，不是公司角色：

- 可在本团队编辑、发布、归档知识。
- 可设置或取消本团队成员的组长标记。
- 不能管理其他团队。
- 不能修改公司级角色。
- 不能把管理员角色授予组员。
- 不能查看其他团队知识或成员私有知识。

组长的权限随团队变化。离开该团队或取消组长标记后，权限立即失效。

## 5. 高风险默认规则

- 价格、成本、利润和客户名单默认不放公司范围。
- 认证、赔付、独家代理和合同承诺必须人工审核。
- 业务员不能修改角色或扩大自己的数据范围。
- 老板角色不可被停用，也不能被删除。
