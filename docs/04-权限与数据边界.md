# Knowhow V2 权限与数据边界

## 1. 为什么不能只做角色名称

“业务员”这个角色并不能说明：

- 能否看到成本、利润和大客户信息。
- 能否看到另一个销售团队的报价。
- 能否发布知识，还是只能提交建议。
- 能否下载原始报价单、邮件和客户资料。

因此权限必须同时覆盖“功能权限”和“数据范围”。

## 2. 两层模型

### 功能权限

控制用户能执行什么动作：

| 权限 | 作用 |
|---|---|
| `ask.use` | 使用销售问答 |
| `knowledge.view` | 查看可见知识 |
| `knowledge.suggest` | 提交知识建议或草稿 |
| `knowledge.edit` | 编辑知识 |
| `knowledge.publish` | 发布和归档知识 |
| `gap.manage` | 处理知识缺口 |
| `dashboard.view` | 查看经营工作台 |
| `team.manage` | 添加、停用成员 |
| `role.manage` | 管理角色和权限模板 |
| `data.all` | 跨团队查看全部数据 |

### 数据范围

每条知识、证据和后续文件都必须有：

- `organization`：全公司可见。
- `team`：指定团队可见。
- `private`：仅负责人或明确授权用户可见。

业务员只能看到：

```text
organization 知识
+ 自己所属 team 的知识
+ 自己的 private 知识
```

老板、管理员或拥有 `data.all` 的角色可以跨团队查看。

## 3. 默认角色

系统提供四个可修改的模板，而不是让老板一开始配置几十个权限点：

| 角色 | 默认能力 | 默认数据范围 |
|---|---|---|
| 老板 | 全部权限 | 全公司 |
| 管理员 | 除企业所有权外的系统管理 | 全公司 |
| 知识负责人 | 查看、编辑、发布、处理缺口、看板 | 全公司 |
| 业务员 | 问答、查看、提交草稿 | 公司 + 本团队 |

老板可以复制模板，创建“某产品线业务员”“财务只读”“客服主管”等角色。

## 4. 文件与证据

原始文件不单独设置一套复杂权限，而是继承所关联知识的可见范围；也可设置比知识更严格的级别。

- 产品公开资料：公司范围。
- 客户聊天、邮件：团队范围。
- 成本表、利润表、客户名单：私有或指定角色。
- 下载行为同样受权限控制并记录审计。

## 5. 高风险默认规则

- 价格、成本、利润和客户名单默认不放公司范围。
- 认证、赔付、独家代理和合同承诺必须人工审核。
- 业务员不能修改角色或扩大自己的数据范围。
- 老板角色不可被停用，也不能被删除。
