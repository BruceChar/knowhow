# P2 产品化与业务连接

## 1. 团队与权限体验

- 团队页面列出所有团队，不依赖用户是否已经成为成员。
- 公司角色唯一跟随账户，不在团队里重复配置。
- 团队成员只需要勾选“组长”，组长权限只作用于该团队。
- 新角色只需要中文名称和权限，内部编码自动生成。
- 知识范围与角色权限分开：角色回答“能做什么”，知识范围回答“能看什么”。

## 2. 成员邀请

邀请链接包含：

- 企业
- 团队
- 角色
- 一次性 token
- 过期时间

成员打开 `/join?token=...`，填写姓名、登录名和密码即可加入，不需要手工创建账号或理解角色编码。

管理员可在团队页查看：

- 本机局域网地址
- 可复制的地址
- 二维码
- 一次性邀请二维码

## 3. 产品事实

产品事实独立于 FAQ：

- product
- product_variant
- price_offer

CSV 最少字段：

```text
sku,name,unit_price,valid_until
```

可选字段：

```text
category,variant_code,variant_name,currency,moq,lead_time_days
```

价格问答优先读取有效、已发布报价。事实缺失时不能由模型补造。

## 4. 经营结果

Interaction 记录客户结果：

- unknown
- following
- won
- lost
- outcome_value

老板看板展示 30 天成交数、成交金额和跟进中数量。

## 5. 部署与升级

```bash
scripts/install.sh
uv run python scripts/doctor.py
scripts/backup.sh
scripts/upgrade.sh
scripts/rollback.sh <commit>
```

## 6. 多客户部署

当前采用：

```text
一个客户 = 一个数据库 + 一个应用部署单元
```

这种模式隔离清晰、备份简单，适合早期产品化。中央客户控制台、许可证和批量升级仍需实现。

## 7. 实时渠道边界

P1/P2 已支持企业微信、WhatsApp、邮件导出文件导入。实时收发还需要：

- 企业主体认证
- 官方开发者账号
- API Key / OAuth
- Webhook 公网域名和验签
- 发送模板及合规审核

没有这些外部条件时不能把“文件导入”伪装成“实时连接”。
