## 2026-11-01：真实闭环复验与检索修复

### 完整业务验收

从全新数据库启动后完成：

```text
初始化公司
→ 导入 2 条 FAQ 草稿
→ 发布并生成 bge-m3 语义索引
→ 英文牵引绳问题命中中文知识，检索模式为 hybrid
→ 修改最终英文回复并标记已发送
→ 记录客户成交结果
→ 导入产品报价
→ 返回 SKU 价格、MOQ、交期和有效期
→ 高风险认证问题转人工并生成知识缺口
→ 从缺口创建并发布知识
→ 新建销售部业务员并验证其提问
→ 新人训练答题 100 分
→ 老板看板显示知识、问答、缺口、采用、训练和成交
```

浏览器验收同时确认：

- 团队页显示“销售部”、2 名成员和业务员所属团队。
- 业务员只能看到销售、知识、待办、报价和训练，不显示团队管理入口。
- 产品事实问答使用 `approved-fact-template`，不依赖模型猜测。

### 发现并修复

- 向量检索曾直接返回 Top-K，导致“巴黎天气”被错误回答成牵引绳知识。
  - 新增可配置最低语义相似度 `KNOWHOW_VECTOR_MIN_SCORE`，默认 `0.35`。
  - 无关问题现在返回无检索结果并转人工，同时生成知识缺口。
- 英文停用词 `you`、`for` 曾制造虚假关键词命中，使认证知识排到牵引绳知识前面。
  - 关键词召回现在过滤常见英文停用词。
  - “Do you offer retractable leashes for large dogs?”继续正确命中“牵引绳分类”。
- 退出账号后，上一账号的问答 DOM 可能残留。
  - 登录页现在清空用户、列表、问答草稿、最终答案和弹窗状态。
- 浏览器可能缓存旧前端资产。
  - HTML 中的 CSS/JS 引用增加构建版本查询参数。

### 工程验证

- `23 passed`。
- Python 编译、JavaScript 语法检查和 `git diff --check` 通过。
- 验收数据库保留初始化公司、3 条已发布知识、1 条产品报价、2 个账户和
  真实交互结果，供后续继续测试。

### 仍需验证

- 当前只使用 3 条知识校准 `0.35` 相似度阈值；接入真实企业数据后必须用
  更完整的黄金集重新标定，避免过严漏召回或过松误回答。
- 产品事实回答仍会展示 Top-K 引用，引用精简和证据相关性评分需要继续优化。
- WhatsApp 实时渠道仍待 Meta 企业应用、号码授权和回调域名，不在本轮完成范围。

```text

业务员访问角色管理/发布接口：403
调整业务员团队后：旧的团队知识立即不可见
```

## 2026-10-31：P1 完成

### 导入

- 支持 CSV、TXT、Markdown 文件。
- CSV 自动识别问题、答案、标题、说话人和消息列。
- 企业微信、WhatsApp、邮件等聊天导出可识别“客户/业务员”对话配对。
- 支持 `Q/A` 段落和 `---` 分隔。
- 预览阶段标记可导入、重复、错误行，并记录批次和 SHA-256。
- 执行导入后只生成待审核知识草稿。

### 知识治理

- 知识负责人可选择和保存。
- 知识有效期可选择，老板看板显示 14 天内到期知识。
- 新建知识时检测相同问题/标题和相同答案；不同答案返回相似知识提示。
- 上传文件批次、重复行和错误行可回看。

### 新人训练

- 训练题从当前用户可见的已发布 FAQ 随机生成。
- 作答后按关键业务信息覆盖率评分。
- 记录每次训练结果、参考答复、缺少要点和准备度。
- 老板看板纳入训练平均分。

### 混合检索

- 使用本地 `BAAI/bge-m3` 生成 1024 维 embedding。
- 知识发布时写入 pgvector，并记录模型名和更新时间。
- HNSW 索引检索向量 Top 候选。
- Jieba 关键词召回作为第二路。
- 加权 RRF 融合两路结果。
- 无 embedding 时自动降级为关键词检索。

真实验收：

```text
CSV 导入 2 条 → 生成 2 条草稿 → 发布并写入 2 个 bge-m3 向量
英文问题 “What leash options do you offer?”
→ 中文“牵引绳分类”知识命中
→ retrieval.mode = hybrid，lexical_candidates = 0
训练题 2 条 → 作答 100 分 → 准备度 100
```

当前限制：

- 模型首次加载约 30 秒；发布 embedding 仍为同步操作，后续应改后台任务。
- “企业微信/WhatsApp/邮件”当前导入的是导出文件，不是官方 API 实时连接。
- 训练评分衡量关键信息覆盖，不替代负责人对表达质量的复核。

## 2026-10-31：P2 基础完成

### 多团队成员与组长

- 公司角色唯一跟随账户，同一人在所有团队使用同一公司角色。
- 团队本身不配置任意角色。
- 多团队知识可见范围取并集。
- 团队成员带一个“组长”标记，组长职责只在对应团队内生效。
- 组长可以编辑、发布本团队知识并调整本团队组长标记。
- 组长不能管理其他团队、公司角色或私有知识。
- 一人可在 A 组任组长、B 组任业务员。

### 团队体验修正

- 团队页展示所有团队，包括尚未添加成员的新团队。
- 团队成员只显示公司角色和是否为组长。
- 新建角色不再要求填写内部编码，系统自动生成。
- 团队、角色、功能权限、知识范围增加中文说明和示例。

### 局域网邀请

- 服务端自动探测局域网 IP。
- “局域网分享”显示可复制地址和二维码。
- “邀请成员”生成一次性邀请链接和二维码。
- 邀请绑定公司、团队和角色，成员自行设置账号密码。
- 链接默认 72 小时过期，使用后不能重复加入。

### 产品报价与客户结果

- CSV 导入产品、变体、币种、价格、MOQ、交期和有效期。
- 同变体新报价会自动让旧报价过期。
- 价格类问题优先使用已发布事实回答，不再依赖知识文本或模型猜测。
- 销售交互可标记跟进中、成交、丢单和成交金额。
- 老板看板展示 30 天成交数和成交金额。

### 部署

- `scripts/install.sh`：环境初始化、启动数据库、迁移和启动应用。
- `scripts/doctor.py`：Python、Docker、uv、PostgreSQL、pgvector、迁移和模型检查。
- `scripts/backup.sh`：PostgreSQL 压缩备份。
- `scripts/upgrade.sh`：先备份，再同步代码、迁移、重建和健康检查。
- `scripts/rollback.sh`：应用代码回退；数据库按备份恢复。
- App 容器增加健康检查和自动重启，模型缓存使用独立持久卷。

真实验收：自定义公司角色自动编码、一次性邀请创建自定义角色账户、局域网二维码、
产品报价导入、SKU 价格问答、成交金额进入老板看板。
