## 任务 #7：防腐层三件套（`app/providers/`）

| 接口 | 协议类 | 实现 | 切换 |
|---|---|---|---|
| `EmbeddingProvider` | `embed(texts)` | `LocalBgeM3Provider`（本地）<br>`ApiEmbeddingProvider`（OpenAI 兼容） | `EMBEDDING_BACKEND` |
| `LLMProvider` | `chat(messages)` | `DeepSeekProvider`<br>`GenericOpenAIProvider`（Qwen/GLM） | `LLM_PROVIDER` |
| `VectorStoreProvider` | `search/upsert` | `PgVectorProvider`（pgvector）<br>`LanceDBProvider`（多模态预留） | `VECTOR_STORE` |

**关键修复**：pgvector 0.5.1 + psycopg 3.3.6 的 `register_vector` 适配器未生效（list 被序列化成 `{...}` 而非 `[...]`），改用**向量文本直传**（`'[' + ','.join(f"{x:.8f}") + ']'`）作为 SQL 参数，检索恢复正常。

**验证**：faq id=1 检索 top3 → 自身 1.0、22 号 0.773、193 号 0.769。

## 任务 #10：管理台 API（`app/admin_api.py`）

**四角色 RBAC**
| 角色 | 能力 |
|---|---|
| `agent` 客服 | 只读检索问答，数据级仅 public+internal |
| `editor` 业务员 | 上传/编辑/打标（编辑后自动回 draft） |
| `reviewer` 审核员 | 审核流 approve/reject |
| `admin` 管理员 | 全部 + 批次管理 |

**数据级权限**：`permission IN (public, internal)` 客服；confidential 需 editor 以上。SQL 层过滤，防越权。

**接口清单**
- `GET /faq?status=&category=&q=`（数据级过滤）
- `GET /faq/{id}` / `PUT /faq/{id}`（编辑+version 递增）
- `POST /faq/{id}/tags`（5 维打标）
- `POST /faq/{id}/approve|reject`（审核流）
- `GET /batches` / `GET /health`

**启动**：`uv run uvicorn app.admin_api:app --port 8000`
**验证**（X-User-Id 头模拟）：客服编辑 403 / 业务员编辑 200 / 审核员通过 200 / 业务员审核 403 / 客服查 confidential 404。

### 5. 性能修复（评测慢的两层）
- **根因**：① 服务进程未带 `HF_HUB_OFFLINE=1` → bge-m3 冷加载反复重连 huggingface.co（每次 10s×5 重试）；② 每次调用 get_embedding_provider() 都新建实例重加载模型
- **修复**：① 启动命令必须带 `HF_HUB_OFFLINE=1`；② admin_api 启动时 `_warmup()` 预热模型；③ embedding_provider 加进程级单例缓存（`_PROVIDER_CACHE`），服务/评测进程内只加载一次
- **实测**：预热后 `POST /eval/run` 33.7s 完成（含首载），后续会更快；门禁 PASS、入库 report id=2
- **遗留**：评测仍是同步接口（CPU 编码 57 条 query 需数十秒）；若需高频触发，下一步改异步任务（POST 返回 task_id + 轮询）
